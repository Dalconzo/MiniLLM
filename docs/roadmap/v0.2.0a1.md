# v0.2.0a1 Roadmap: Operational Personal World Model

`v0.2.0a1` is the recommended next substantive release. It should move MiniLLM
from governed transcript retrieval toward an operational personal world model.
Job search is the first real domain because its state changes are concrete and
auditable; synthetic baking fixtures remain the low-risk regression domain.

This document defines scope only. None of these features are implemented by the
public-consistency cleanup that introduced this roadmap.

## Delivery Slices

The v0.2 work is intentionally divided into three independently releasable
alphas. A later slice must not be used to keep an earlier slice open after its
own acceptance criteria pass.

### `v0.2.0a1`: Retrieval and state foundation

- Populate and validate near-complete corpus embeddings with resumable batches,
  model/version metadata, stale detection, and explicit degraded-mode health.
- Add the generic object, event, claim, claim-evidence, relationship, and
  materialized-state schema with migrations and provenance invariants.
- Implement the smallest job-search vertical slice: company, role, application,
  application-stage event, and derived current application state.
- Replace baking-specific current-state branches with schema-driven temporal and
  provenance rules while retaining the synthetic baking regression cases.
- Ship focused retrieval/state evaluations for semantic recall, supersession,
  attribution, provenance, and no-answer behavior.

Exit criterion: a clean-clone build can ingest a synthetic history, reach the
declared embedding-health threshold, reconstruct a job application's current
state from append-only events, and compile a source-backed context packet
without domain-specific state code.

### `v0.2.0a2`: Safe job-search workspace operations

- Add project-note patch/update operations with expected-revision checks,
  previewed diffs, Git snapshots, explicit approval, and rollback evidence.
- Add bounded PDF and DOCX text extraction with strict path, size, type,
  decompression, privacy, and persistence controls.
- Expand the job-search model to people, resume versions, interviews, projects,
  next actions, and source-backed document relationships.

Exit criterion: an authorized client can maintain a versioned job-search
workspace and retrieve its text artifacts without unrestricted filesystem
access, silent overwrite, or external document processing.

### `v0.2.0a3`: Combined-memory usefulness evaluation

- Execute the same predeclared task set against no memory, ChatGPT/platform
  memory, local structured memory, raw-history RAG, and combined memory.
- Measure generated-answer quality, personalization, provenance, stale-state
  use, misattribution, context cost, and latency.
- Retain exact variant identities and machine-readable evidence; do not label a
  planned or simulated adapter as an executed platform-memory condition.

Exit criterion: the combined-memory claim is limited to results produced by
actually executed variants, and any production promotion remains human-gated.

## Milestone Outcomes

### Durable evidence and embeddings

- Reach near-complete production embedding coverage with resumable batches,
  deterministic retry behavior, per-chunk model/version metadata, missing/stale
  counts, and an explicit degraded mode when coverage is insufficient.
- Preserve raw transcript chunks as immutable evidence rather than treating
  retrieval results as current truth.

### Generic world-model core

- Add generic persistent objects, events, claims, claim evidence, relationships,
  and materialized current state with provenance on every derived field.
- Make events append-only. Rebuild current state from ordered evidence so a
  correction or newer volatile fact supersedes rather than erases history.
- Require an explicit human promotion gate before extracted candidates can
  become trusted claims or change materialized state.

### Job-search domain

- Represent companies, roles, applications, people, resume versions,
  interviews, and projects as typed objects on the generic core.
- Record application-stage changes as append-only events and derive the current
  stage from source-backed chronology.
- Apply temporal policies to volatile claims including application status,
  location, contact relationship, next action, and active resume version.
- Expose uncertainty, conflicts, missing provenance, and stale state rather
  than silently selecting a plausible value.

### Context and document operations

- Replace baking-specific state logic with a domain-neutral context compiler
  driven by object type, task, temporal validity, provenance, and disclosure
  policy. Synthetic baking scenarios must still pass without hardcoded baking
  branches.
- Add safe project-note patch/update operations using relative authorized paths,
  expected-revision checks, previewed diffs, Git snapshots, explicit approval,
  and rollback evidence.
- Add PDF and DOCX extraction behind strict path, size, type, decompression,
  privacy, and persistence boundaries. Extraction failures must be explicit and
  must not fall through to unrestricted tools or external services.

## Evaluation Contract

Execute the same versioned task set against:

1. no memory;
2. ChatGPT/platform memory;
3. local structured memory;
4. raw-history RAG;
5. combined platform and local memory.

Every label must correspond to an actually executed variant. Predeclare
thresholds and retain machine-readable results for generated-answer quality,
personalization, provenance accuracy, stale-state use, user/assistant
misattribution, context-token cost, and latency. Include no-answer, conflicting
state, missing provenance, sensitive-data, and temporal-supersession cases.

The overall v0.2 milestone is complete only after all three alpha slices pass
their own clean-clone gates. Each alpha must retain the limited prototype claim
unless its separate public evidence supports stronger language.
